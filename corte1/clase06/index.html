Paso 2 · Las Cuatro Decisiones de Diseño ⚖️

Frente a cada columna del Excel solo existen cuatro decisiones posibles:

Note🗑️ 1. DESCARTAR

La columna no aporta información. Casos: 100 % vacía (FECHA DE INSTALACION) o un solo valor repetido en todas las filas (CONDICIONES DE TRABAJO, FRECUENCIA DE ALIMENTACION, RESPONSABLE MANTENIMIENTO). Un campo constante ocupa espacio, no permite filtrar y no responde ninguna pregunta.

Note✅ 2. CONSERVAR TAL CUAL

El dato es atómico y no tiene dominio cerrado. Casos: NOMBRE DEL EQUIPO, MARCA, MODELO, SERIE. Se tipifican como VARCHAR(n) con una longitud justificada.

Note✂️ 3. DIVIDIR (una columna → dos o más)

El dato no es atómico: mezcla valor y unidad, o es un rango. TEMPERATURA = 0 - 43°C se convierte en TempMin y TempMax. VOLTAJE = 110 VAC se convierte en VoltajeValor (INT) y VoltajeTipo (VAC/VDC). Regla: si no puede ordenar, filtrar ni promediar el campo, es porque no está dividido.

Note🔗 4. NORMALIZAR (columna → tabla de dominio + FOREIGN KEY)

El dato pertenece a una lista cerrada que se repite. Casos: CLASIFICACION BIOMEDICA, CLASIFICACION SEGÚN RIESGO, TECNOLOGIA PREDOMINANTE, FRECUENCIA MPP, UBICACIÓN(servicio). Se crea una tabla aparte y en inventario queda solo el código. Esto es lo que impide que existan Diagnostico, diagnostico y DIAGNOSTICO como si fueran tres cosas distintas.

Important⚠️ La pregunta que decide todo

Para cada columna pregúntese: “¿qué consulta quiero poder hacer con este dato?”

  • “¿Cuántos equipos de soporte de vida hay en la UCI?” → CLASIFICACION BIOMEDICA y SERVICIO deben estar normalizados.
  • “¿Cuáles equipos pesan más de 100 kg?” → PESO debe estar dividido y en una sola unidad.
  • “¿Cuántos equipos trabajan a 60 Hz?” → nadie hace esa consulta, y además todos son iguales → descartar.

5.2 Bonus: la criticidad que define la frecuencia de mantenimiento

La hoja MPP de BD.xlsx califica cada equipo con 4 variables de 1 a 5 (frecuencia de uso, forma de uso, exactitud requerida, importancia económica). La suma define el período: 4–8 anual · 9–13 semestral · 14–17 trimestral · 18–20 bimestral.

Eso no se escribe a mano: se calcula.

CREATE TABLE IF NOT EXISTS criticidad (
  IdCriticidad   INT AUTO_INCREMENT PRIMARY KEY,
  IdEquipo       INT NOT NULL,
  FrecuenciaUso  TINYINT NOT NULL,
  FormaUso       TINYINT NOT NULL,
  ExactitudReq   TINYINT NOT NULL,
  ImportanciaEco TINYINT NOT NULL,
  -- Columna generada: MySQL la calcula sola, nadie la puede desincronizar
  PuntajeTotal   TINYINT AS (FrecuenciaUso + FormaUso + ExactitudReq + ImportanciaEco) STORED,
  CONSTRAINT fk_crit_equipo FOREIGN KEY (IdEquipo) REFERENCES inventario(IdEquipo),
  CONSTRAINT ck_rangos CHECK (
       FrecuenciaUso  BETWEEN 1 AND 5
   AND FormaUso       BETWEEN 1 AND 5
   AND ExactitudReq   BETWEEN 1 AND 5
   AND ImportanciaEco BETWEEN 1 AND 5)
) ENGINE=InnoDB;

-- Vista que traduce el puntaje al periodo de mantenimiento
CREATE OR REPLACE VIEW v_cronograma_mpp AS
SELECT i.IdEquipo, i.NombreEquipo, s.Nombre AS Servicio, c.PuntajeTotal,
       CASE
         WHEN c.PuntajeTotal BETWEEN 18 AND 20 THEN 'BIMESTRAL'
         WHEN c.PuntajeTotal BETWEEN 14 AND 17 THEN 'TRIMESTRAL'
         WHEN c.PuntajeTotal BETWEEN  9 AND 13 THEN 'SEMESTRAL'
         ELSE 'ANUAL'
       END AS PeriodoMpp
FROM criticidad c
JOIN inventario i ON i.IdEquipo = c.IdEquipo
JOIN servicios  s ON s.IdServicio = i.IdServicio;

<?php
// api/guardar.php
require 'conexion.php';

// ---------- Campos que acepta el formulario (= diccionario de datos) ----------
$campos = ['ActivoFijo','Placa','NombreEquipo','Marca','Modelo','Serie','AnioFabricacion',

    $v = $_POST[$c] ?? '';
    $datos[$c] = ($v === '') ? null : $v;   // vacio en el formulario = NULL en la BD
}

// ---------- Validaciones minimas (las que exige el diccionario) ----------
$errores = [];
if (empty($datos['ActivoFijo']))        $errores[] = 'El activo fijo es obligatorio.';

if (empty($datos['IdServicio']))        $errores[] = 'Debe seleccionar el servicio.';
if (empty($datos['IdClasifBiomedica'])) $errores[] = 'Debe seleccionar la clasificacion biomedica.';
if (empty($datos['IdClasifRiesgo']))    $errores[] = 'Debe seleccionar la clasificacion de riesgo.';

if (!empty($datos['AnioFabricacion'])) {
    $anio = (int)$datos['AnioFabricacion'];

        $errores[] = 'El anio de fabricacion debe estar entre 1950 y ' . date('Y') . '.';
    }
}

$guardado = false;
$mensajeError = '';

        $stmt->execute();
        $stmt->close();
        $guardado = true;

        if ($e->getCode() == 1062) {                 // viola UNIQUE

        } else {
            $mensajeError = 'Error al guardar: ' . $e->getMessage();
        }
    }
}

Important⚠️ PHP 8 cambió cómo se reportan los errores de MySQL

XAMPP hoy trae PHP 8, y ahí mysqli lanza excepciones en lugar de devolver false. Por eso el INSERT va dentro de un try / catch.

Si copia el patrón antiguo if ($stmt->execute()) { ... } else { ... }, el bloque else nunca se ejecuta: al registrar un activo fijo repetido el estudiante no verá su mensaje, verá una pantalla blanca con Fatal error: Uncaught mysqli_sql_exception. Es el error más frecuente de esta práctica.

Important🔐 Diferencia clave con la Guía WEB

La guía arma el INSERT concatenando las variables: "... VALUES ('$Placa', '$NombreEquipo', ...)". Eso funciona, pero permite inyección SQL: si alguien escribe '; DROP TABLE inventario; -- en el formulario, la base se destruye.

Aquí usamos prepare() + bind_param(): los datos viajan separados de la sentencia SQL y esa clase de ataque deja de ser posible. En un sistema hospitalario esto no es opcional.

💡 Qué significa cada ataque, en palabras sencillas

Inyección SQL. Si el INSERT se arma pegando texto ("... '$Marca' ..."), el usuario puede escribir en el formulario algo que el servidor confunde con instrucciones SQL en vez de con un dato. Con eso puede leer toda la base, cambiarla o borrarla. La consulta preparada lo evita porque el dato viaja por un canal separado y nunca se interpreta como instrucción.

XSS (Cross-Site Scripting). Si usted imprime en la tabla lo que alguien guardó, y esa persona guardó <script>…</script> en el campo Marca, ese código se ejecuta en el navegador de quien consulte el inventario. htmlspecialchars() lo convierte en texto visible e inofensivo.
